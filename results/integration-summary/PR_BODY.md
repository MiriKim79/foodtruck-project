## 3. 최종 채택 전략

`ORDER_GATE=false`, `COOK_MODE="DP"`, `PROMOTION_LIMIT=false`, `PROMO_END_MARGIN=4` (접수 기존 방식 + 제조 DP + 기존 홍보).

- 직원 우선순위는 제조 > 접수 > 홍보이고, 진행 중 작업 KEEP과 동일 작업 중복 배치 금지를 유지합니다.
- 설정값 4개는 코드 상단 상수이며 독립적으로 바꿀 수 있습니다(미사용 분기는 비교 재현을 위해 남겼습니다).
- **선정 이유**:
  1. 공개·신규·홀드아웃 세 집합 모두에서 main 대비 하락 시드가 0개입니다.
  2. 접수 정밀 마감 판단(게이트 ON)보다 신규·홀드아웃에서 일관되게 높았습니다. 게이트가 켜져 있으면 제조 모드(SJF/DP)를 바꿔도 매출이 같았습니다(공개 C2=C3=C4, 신규 C2=C4). 환불은 매출에서 빠지는 손실이 아니므로 환불 0원은 목표가 아니었고, 접수를 거절하면 마감 직전 DP가 고를 선택지가 줄어드는 것으로 추정됩니다(별도 실험으로 검증하지는 않았습니다).
  3. 제조 직원이 경기당 약 99.9% 가동되는 상태라 제조 처리량이 병목이고, 개선 폭은 0.6% 수준으로 작습니다.

## 7. 알려진 한계

- **다른 상대에 대한 검증은 수행하지 않았습니다.** 모든 실험의 상대는 main 기준 전략 1종입니다. 공식 비공개 시드·상대의 성능도 확인하지 못했습니다.
- 개선 폭이 +0.6% 수준으로 작고, 최종 후보는 공개·신규 시드로 선정했습니다(홀드아웃만 선정에 사용하지 않음).
- **PR #4 보고서의 기준값 559,750원은 동일 조건(main 기준 전략, 공개 시드 20경기)에서 재현하지 못했습니다.** 같은 코드끼리 붙인 기준은 557,500원이었고 PR #2·#3 보고서와 일치했습니다. 559,750원이 나온 조건(코드·상대·집계 방식)은 확인되지 않았으며, 기록 오류라고 단정하지 않습니다. 같은 기준(557,500원) 대비 DP의 개선은 +3,500원으로 측정됐고, PR #4가 보고한 DP 점수 561,000원은 재현됐습니다.
- 홍보 제한은 공개 +400, 신규 −350(CI [−875, +100])으로 일관된 근거가 없어 채택하지 않았습니다. 홀드아웃에서는 홍보 제한을 실험하지 않았습니다.
- 환불 주문이 경기당 약 4.4건 남지만 환불은 매출에 포함되지 않습니다. 마감 불가 주문만 거절하는 완화형 게이트는 구현·실험하지 않았습니다.
- 줄바꿈은 저장소 설정에 따라 LF가 CRLF로 바뀐다는 git 경고가 있습니다(기존 파일과 동일).
