# C-Lab 푸드트럭 v0.16 학생용 · 평가 규칙 연습

이 버전은 학생이 Java로 전략을 작성하도록 만든 별도 배포본입니다. 기존 ZIP과 다른 폴더에 압축을 풀고, 이전에 작성한 `MyStrategy.java`만 새 폴더의 같은 경로로 복사하세요. Java 전략 형식은 바뀌지 않았습니다. 내부 시뮬레이션 엔진과 화면은 JavaScript이고, **학생 제출물은 Java**입니다. 전체 엔진을 Java로 다시 만든 버전은 아닙니다.

## 학생이 수정할 파일
- A팀: `teams/A/MyStrategy.java`
- B팀: `teams/B/MyStrategy.java`
- 두 팀 모두 파일명/클래스명은 `MyStrategy`입니다. 다른 폴더와 별도 Java 프로세스로 실행합니다.
- `choose(Game.View view)`에서 `Game.Action[2]`를 반환합니다. 배열 0/1은 각 직원입니다.
- `java/Game.java`는 공개 자료형 설명입니다. 엔진·실행기·평가기를 수정하지 마세요.

`view.workers()`, `orderQueue()`, `cookQueue()`, `customers()`, `menus()`, `now()`, `horizon()`, `workload()`, `revenue()`, `escrow()`를 사용할 수 있습니다. 추가 원본 관측 필드는 `raw()`에 있습니다. 고객 구매력은 `budget()`, 기본 구매확률은 `probability()`, 해당 트럭 관심은 `interest()`입니다. 주문의 `cookTime()`은 묶음 전체 제조시간입니다.

행동은 `Game.Action.keep()`, `waitAction()`, `promote()`, `takeOrder(주문ID)`, `cook(주문ID)`입니다. 진행 중 작업은 KEEP으로 유지해야 하고, 같은 구역에 두 직원을 배치할 수 없습니다. 매 경기 새 프로세스로 시작하므로 클래스 필드는 경기 사이에 공유되지 않습니다.

## 실행 전 준비
전략을 수정·평가할 컴퓨터에 **JDK 17 이상(컴파일러 포함)** 및 **Node.js 18 이상**이 필요합니다. Java/Node를 설치하는 작업은 이 ZIP이 자동으로 하지 않습니다. 터미널에서 `java --version`, `node --version`을 확인하세요. Java 설치에 `jdk.compiler` 모듈이 없으면 JDK 설치가 필요합니다. Java 21·Node 24의 Linux 환경에서 검증했습니다. Mac/Windows에서는 아직 직접 실행 검증하지 않았습니다.

### 맥북
1. ZIP을 새 폴더에 모두 풉니다. A/B 파일을 수정하고 저장합니다.
2. 터미널에서 해당 폴더로 이동 후 `bash Run-Mac.command`를 실행합니다. 실행 권한이 유지되면 파일을 직접 열어도 됩니다.
3. 컴파일과 300틱 경기가 끝나면 `results/game.html`이 기본 브라우저에서 열립니다.

### Windows
ZIP을 새 폴더에 풀고 `Run-Windows.bat`을 실행합니다. 또는 폴더 터미널에서 `node run.js`를 실행한 뒤 `results/game.html`을 여세요.

직접 명령: `node run.js 2026` (시드). 전체 혼잡도 일정은 별도 입력 없이 시드로 결정합니다. 운영진 평가 시드와 공개 연습 시드는 다릅니다. 이 버전은 **경기를 먼저 계산한 뒤 기록을 재생**합니다. HTML만 열어 Java 코드를 실시간 실행하는 방식이 아닙니다. HTML 안의 재생·1틱·슬라이더는 저장된 경기를 보는 기능입니다. 코드를 바꾸면 다시 실행하고 HTML도 새로 열어야 합니다. 파일을 받기만 해서 예시를 볼 때는 JDK/Node 없이 포함된 `results/example.html`을 열 수 있습니다.

발표자는 PPT 파일로 발표합니다. Java 실행과 브라우저 시연은 필수 발표 준비물이 아니며, 학생 실습 때 위 절차를 사용합니다.

## 두 팀 평가
`node run.js --benchmark`를 실행합니다. 5개 시드 × A/B 자리 교대 × 좌우반전 = 20경기이며 `results/comparison.json`에 저장됩니다. 독립 시드는 5개이고 20개 독립 표본이 아닙니다. 두 팀에 같은 기본 전략이 들어 있으므로 두 팀 평균이 일치해야 합니다. 전략이 다르면 평균도 달라질 수 있습니다.

## v0.16 평가 규칙
2팀, 팀별 직원 2명, 300틱. 홍보 3틱·계산 주문당 2틱·최대 3음식. 메뉴별 가격/제조는 빠른 4,000원/2틱, 보통 6,000원/3틱, 고급 9,000원/5틱으로 고정입니다. 이전 v0.15의 고급 4틱과 달리 5틱입니다. 같은 메뉴의 제조시간은 주문마다 무작위로 바뀌지 않습니다. 묶음은 메뉴의 시간과 가격을 각각 더합니다.
- 경기 중 전부 제조를 완료한 주문만 확정 매출로 기록됩니다. 결제 후 미완료는 전액 환불합니다. 동일 경기 수의 확정 매출 합계만으로 평가 순위를 매기며, 같으면 공동 순위입니다.
- 처음 40틱은 보통, 40·120·200·280틱에 직전과 다른 혼잡도로 바뀝니다. 이후 각 혼잡도는 80틱간 유지되며 마지막 구간은 경기 끝(300틱)까지 20틱입니다. 240틱에는 별도 마감 안내가 나옵니다.
- 현재 혼잡도와 전환 여부는 선택적으로 `view.raw().get("trafficLevel")`, `view.raw().get("trafficChanged")`에서 확인할 수 있습니다. 기존 코드는 수정 없이 동작합니다. 전략에 미래 일정은 전달되지 않습니다.

## 오류와 보안 한계
컴파일 오류는 팀과 함께 터미널에 표시합니다. 최초 Java 준비 10초, 행동 응답 2초 제한이며, 오류·종료·시간초과는 해당 팀 실패로 처리합니다. 엔진이 행동 유효성도 검사합니다. 컴퓨터 성능·부하 때문에 제한이 영향을 받을 수 있으므로 평가는 같은 기기에서 진행하세요. 디버깅은 `System.err.println`을 쓰세요. `System.out`도 stderr로 돌리지만 실행기 프로토콜을 직접 조작하면 안 됩니다.

이것은 **보안 샌드박스가 아닙니다**. Java 코드는 사용자 권한으로 파일·네트워크에 접근할 수 있습니다. 신뢰하는 직접 검토한 제출물만 실행하세요. 메모리/시간 제한은 보안 격리나 부정행위 방지 장치가 아닙니다.

## 배포 검수 범위
기존 회귀검사 142개와 Java 연결검사 4개를 통과한 v0.12를 바탕으로 실행에 필요한 파일만 묶었습니다. Linux에서 실행을 확인했으며 Mac/Windows 실기기 및 실제 브라우저 화면은 미검증입니다.

미리 포함된 예시는 results/example.html입니다. 새 경기 실행 후에는 results/game.html이 생성됩니다. 학생은 Java 전략 파일만 수정합니다.

## 화면과 배포 구분
리플레이가 가장 위에 표시됩니다. 우측 ‘주문 영수증 열기’로 종이 영수증 모달을 열고 닫기 또는 Esc로 돌아옵니다. 팀·처리 필터, 전체 영수증 CSV, 현재 필터의 영수증 및 정산 인쇄/PDF를 지원합니다. 직원별 간트차트는 접고 펼칠 수 있으며 막대를 누르면 해당 시점으로 이동합니다.
이 ZIP은 Windows와 Mac 실행기를 함께 담은 단일 학생 프로젝트입니다. 기본 A/B 예제 전략은 학습 시작용이며 최적해/정답이 아닙니다. 발표·교사용 해설·운영진 평가 실행기·최종 평가 설정/결과는 포함하지 않았습니다. 공개 연습용 --benchmark는 그대로 제공합니다.
학생용과 운영진용은 동일한 경기 엔진·혼잡도 규칙·실행기를 사용합니다. 공식 실행기와 비공개 시드는 배포하지 않습니다.
