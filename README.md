# foodtruck-project

## 프로젝트 목표
300틱 동안 직원 2명의 홍보·주문 접수·제조 작업을 최적화하여 최종 확정 매출을 최대화한다.

## 역할 분담

| 담당 | 역할 |
|---|---|
| 유호승 | 제조 스케줄링 및 마감 최적화 |
| 이은샘 | 주문 접수 및 대기열 최적화 |
| 정승빈 | 홍보·혼잡도 대응 및 직원 배치 |
| 김미 | GitHub 관리, 전략 통합, 보고서 및 발표 |

## 개발 규칙
- 실제 전략 수정 대상: `teams/A/MyStrategy.java`
- 게임 엔진 및 실행 관련 파일은 수정하지 않는다.
- 각자 담당 브랜치에서 개발하고 Pull Request를 생성한다.
- PR은 통합 담당자가 검토하며, 개별 전략을 바로 main에 병합하지 않는다.
- 최종 제출 전략 코드는 하나의 `MyStrategy.java`로 통합한다.

## 브랜치
- `main`: 기본 코드 및 통합 완료 코드
- `feat/cook`: 제조·마감 전략
- `feat/order`: 주문 접수 전략
- `feat/promotion`: 홍보·직원 배치 전략
- `feat/integration`: 최종 전략 통합

## 팀원별 공유 결과물
1. 전략 코드 및 PR
2. 기준 전략과 개선 전략의 성능 비교표
3. 전략 선택 이유, 수정 사항, 실험 결과, 실패 원인
4. 발표용 그래프 및 대표 리플레이 캡처

## 공통 실험 원칙
- 동일한 경기 조건과 시드로 비교한다.
- 한 번에 하나의 전략 요소를 변경하여 영향을 확인한다.
- 확정 매출을 핵심 지표로 사용한다.
- 완료 주문 수, 미완료 주문 수, 환불액 및 오류 여부를 함께 기록한다.
- 가장 좋은 결과뿐 아니라 실패 사례도 공유한다.
