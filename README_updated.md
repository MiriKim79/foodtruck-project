# Foodtruck Scheduling Project

C-Lab 푸드트럭 v0.16 기반의 **4인 팀 스케줄링 전략 프로젝트**입니다. 직원 2명의 홍보·주문 접수·제조 작업을 조정하여, **300틱 마감까지 제조를 완료한 주문의 확정 매출 합계**를 최대화합니다.

> **수정·제출 대상:** `teams/A/MyStrategy.java` 하나입니다. 제공된 게임 엔진, 실행기, 평가기 코드는 변경하지 않습니다.

## 팀 역할 및 협업 문서

| 담당 | 역할 | 공유 결과물 |
| --- | --- | --- |

| 팀원 2 | 주문 접수 및 대기열 전략 | 전략 코드(PR), 성능 비교표, 전략·실패 분석, 발표용 자료 |

## GitHub 작업 규칙

| 브랜치 | 용도 |
| --- | --- |
| `main` | 제공된 기본 코드 및 검증 완료한 통합 코드 |
| `feat/cook` | 제조·마감 전략 실험 |
| `feat/order` | 주문 접수·대기열 전략 실험 |
| `feat/promotion` | 홍보·혼잡도·직원 배치 전략 실험 |
| `feat/integration` | 통합 및 최종 검증 |

1. 자신의 브랜치에서 `teams/A/MyStrategy.java`를 수정하고 실험합니다.
2. 실험 결과와 전략 선택 이유를 기록한 뒤 **Pull Request를 생성**합니다.
3. 여러 브랜치가 동일 파일을 수정하므로 개별 PR을 바로 `main`에 병합하지 않습니다. 통합 담당자가 검토 후 전략을 선별·통합합니다.
4. 비교할 때는 **같은 시드·상대 전략·A/B 위치·혼잡도 조건**을 사용합니다. 핵심 지표는 확정 매출이며 완료 주문 수, 미완료 주문 수, 환불, 실행 오류를 보조 지표로 기록합니다.
5. 최종 제출용 전략은 `teams/A/MyStrategy.java`에 하나로 통합합니다.

## 실행 준비 및 방법

- **JDK 17 이상(컴파일러 포함)**, **Node.js 18 이상**이 필요합니다.
- 설치 확인: `java --version`, `node --version`
- 제공 자료는 Linux(JDK 21·Node.js 24)에서 검증되었습니다. 원본 안내에 따르면 Mac·Windows 실기기 검증은 완료되지 않았습니다.

### Windows

프로젝트 최상위 폴더에서 `Run-Windows.bat`을 실행하거나, 터미널에서 아래 명령을 실행합니다.

```bash
node run.js
```

### macOS

프로젝트 최상위 폴더에서 다음을 실행합니다.

```bash
bash Run-Mac.command
```

### 시드 지정 및 결과 확인

```bash
node run.js 2026
```

경기가 계산된 뒤 `results/game.html`에서 리플레이를 확인합니다. 전략 코드를 수정했다면 **다시 실행해서 새 리플레이를 생성**해야 합니다. 실행 없이 예시만 보고 싶다면 `results/example.html`을 열면 됩니다.

### 기본 벤치마크

```bash
node run.js --benchmark
```

제공된 공개 벤치마크는 **5개 시드 × A/B 자리 교대 × 좌우반전 = 20경기**이며, `results/comparison.json`에 저장됩니다. 독립 시드는 5개이므로 20경기를 20개의 독립 표본으로 해석하면 안 됩니다. 공식 평가에는 비공개 시드가 사용됩니다.

## 게임 규칙(v0.16)

| 항목 | 규칙 |
| --- | --- |
| 경기 | 2팀, 각 팀 직원 2명, 300틱 |
| 홍보 | 3틱 |
| 주문 접수·계산 | 주문당 2틱 |
| 주문 | 최대 3개 메뉴를 묶어서 구매 가능 |
| 빠른 메뉴 | 4,000원 / 제조 2틱 |
| 보통 메뉴 | 6,000원 / 제조 3틱 |
| 고급 메뉴 | 9,000원 / 제조 **5틱** |
| 평가 | 마감까지 **제조 완료한 주문의 확정 매출 합계** |

- 묶음 주문의 가격과 제조시간은 각 메뉴의 합계입니다.
- 결제 후 제조 미완료 주문은 마감 시 전액 환불됩니다.
- 혼잡도는 처음 40틱 동안 '보통'이며 **40·120·200·280틱**에 직전과 다른 단계로 바뀝니다. **240틱**에는 별도 마감 안내가 표시됩니다.
- 전략은 미래 혼잡도 일정을 전달받지 않습니다. 현재 혼잡도 및 변화 여부는 `view.raw().get("trafficLevel")`, `view.raw().get("trafficChanged")`에서 선택적으로 확인할 수 있습니다.

## 전략 구현 참고

- `MyStrategy`의 `choose(Game.View view)`가 **직원 2명의 행동을 담은 `Game.Action[2]`**를 반환합니다.
- 참고 관측값: `view.workers()`, `orderQueue()`, `cookQueue()`, `customers()`, `menus()`, `now()`, `horizon()`, `workload()`, `revenue()`, `escrow()`; 추가 원본 정보는 `raw()`를 참고합니다.
- 고객 정보에는 `budget()`, `probability()`, `interest()`가 있으며 주문의 `cookTime()`은 **묶음 전체 제조시간**입니다.
- 가능한 행동: `Game.Action.keep()`, `waitAction()`, `promote()`, `takeOrder(orderId)`, `cook(orderId)`.
- 진행 중 작업은 반드시 `KEEP`하고, 같은 작업 종류에 직원 2명을 동시에 배정하면 안 됩니다.
- 각 경기는 새 Java 프로세스로 시작되므로 클래스 필드의 값은 경기 간 유지되지 않습니다.
- `java/Game.java`는 전략 작성을 위한 API 참고 파일입니다. **엔진·실행기·평가기 코드는 수정하지 않습니다.**

## 오류 및 실행 시 주의사항

- 제공 실행기는 최초 Java 준비 **10초**, 행동 응답 **2초** 제한을 둡니다. 컴파일 오류·시간초과·프로세스 종료·무효 행동은 해당 팀의 실패로 처리될 수 있습니다.
- 디버깅 출력은 `System.err.println`을 사용합니다. 실행기 통신 프로토콜을 직접 조작하지 않습니다.
- Java 전략은 로컬 사용자 권한으로 파일·네트워크에 접근할 수 있으므로 **신뢰하고 검토한 코드만 실행**합니다. 이 실행 환경은 보안 샌드박스가 아닙니다.
- 비교 실험은 가능하면 같은 컴퓨터·환경에서 실행합니다.
- HTML 화면은 이미 계산된 경기의 **기록 재생용**입니다. 주문 영수증, 정산, 직원 간트차트를 통해 결과를 분석할 수 있습니다.
- 발표는 **PPT 파일**로 진행하며, Java 실행 또는 브라우저 실시간 시연은 필수 발표 준비물이 아닙니다.
